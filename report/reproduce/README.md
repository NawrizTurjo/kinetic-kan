# Reproducing the report's figures, tables and numbers

Everything in the report that is not a raw training output is regenerated by the
scripts in this folder. **Nothing here trains a model.** Every input is a saved run
under `implementation/results/` (its `metrics.json`, `training_history.json` and
`best_model.pt`), or the solver tableaux and basis functions in `implementation/`.

## Run it

From the repository root:

```bash
pip install -r requirements.txt                    # repository root; covers everything here
python report/reproduce/run_all.py                 # all steps, then build report/report.pdf
python report/reproduce/run_all.py --no-report     # all steps, skip the LaTeX build
python report/reproduce/run_all.py s07 s09         # only the named steps (prefix match)
python report/reproduce/collect_result_figures.py --check   # verify copied plots, copy nothing
```

`run_all.py` runs each step in its own process, in order, and stops at the first
failure. The whole pipeline takes a few minutes on a laptop CPU, plus about a minute
for the report build. The ACM version is built separately:

```bash
cd report-acm
../report/tools/tectonic.exe -k A_08.tex           # writes A_08.pdf
```

Both reports read their figures from `report/figures/` (the ACM build sets
`\graphicspath{{../report/}}`), so one run of the pipeline updates both.

`requirements.txt` in this folder pins the versions the figures were generated with
(Python 3.11.1, Windows 11, CPU only).

## Notes

* **Paper-settings tanh MLP.** Wherever the report plots or tabulates "the tanh MLP"
  outside the KAN-vs-MLP table's default-settings column and the controlled
  breakdown after it, the run is the paper-settings one above, not
  `benchmarks/mlpode_baseline`. That is why `s15` and `s16` redraw two plots that
  `implementation/phase2_closeout.py` originally produced with the default run;
  re-running `phase2_closeout.py` still writes the old versions into
  `implementation/results/figures/`, which the report no longer uses.
* **Missing `dt` in the paper-settings checkpoints.** They were saved by the Kaggle
  script, whose config omits `dt`. Their 141 points on [0, 14] are the same 0.1 grid
  every other run uses, and `s16` defaults to it.
* **Cloud-trained checkpoints** re-scored on a different CPU reproduce their stored
  extrapolation MSE to within 0.62% (`s00`); everything else matches far more tightly.
